# 칼람 0.4 시험 결과 (2026-11-15 밤)

0.3.1의 소스에서 고쳐 0.4를 만들었습니다.
판정: **됨**은 이 폴더의 앱 기록(`앱기록_logcat.txt`, 태그 `Carlarm`)에 보낸 값과 다시 읽은 값이 남은 것만. **안 됨**은 해 보았는데 되지 않은 것, **지원 안 함**은 에뮬레이터가 그 장치를 갖지 않은 것(능력 확인 실패), **돌려 보지 않음**은 시험하지 못한 것.

## 층 1~4 (아래는 시험하며 채움)

## 시험 환경

debug 빌드(0.4, versionCode 5)를 에뮬레이터 emulator-5554(Pleos Connect, API 34)에 깔았습니다. 0.3.1 release(다른 서명)가 깔려 있어 지우고 깔았습니다(에뮬레이터의 칼람 앱 데이터가 지워짐). 가상 콘솔을 켜 둔 채(1초마다 세션 요청) 콘솔의 운전석 시트를 앞뒤 50, 등받이 60, 높이 50, 기울기 40, 허리 50으로 놓고, 차 상태를 `콘솔_차상태.log`에 적었습니다. 빠르게 보기(1분 = 2초)로 돌렸습니다.

에뮬레이터에서 본 한계(앱 기록과 콘솔 값으로 확인):
- SDK의 시트 위치 읽기(`getCurrentSeat…Position`)는 열 축 모두 늘 0을 돌려줍니다. 콘솔의 위치(등받이 60 등)와 다릅니다. 반면 SDK의 움직이기(`moveSeat…`)는 콘솔에 닿습니다(20:05:18 `moveSeatBackrestAngle FORWARD` 뒤 콘솔 등받이 60 → 100, 20:09:15~17 `moveSeatTilt FORWARD` 뒤 콘솔 기울기 40 → 80, 차 화면에 시스템의 "시트 위치 변경됨" 알림, 그림 `4a_…`).
- 그래서 "위치를 읽으며 움직이고 목표에서 STOP"은 에뮬레이터에서 확인하지 못했습니다. 앱은 0.8초 동안 위치 값이 바뀌지 않으면 멈추고(위치를 확인하지 못한 움직임), 되돌릴 때 보낸 시간만큼 반대로 움직인 뒤 화면에 "시트 자세를 직접 확인해 주세요"를 보입니다(20:10:01~06 기록, 콘솔 기울기 80 → 40으로 돌아옴, 그림 `7b_…`).
- 등받이는 위치가 0(AAOS에서 가장 눕힌 자리)으로 읽혀, 앱이 "이미 가장 눕힌 자리"로 보고 움직이지 않았습니다. 그래서 에뮬레이터에서 등받이 눕히기와 "등받이를 세우고 출발하세요"는 보지 못했습니다.
- SDK의 뒷자리 탑승 값은 셋 다 true로 읽혔고(콘솔은 뒷자리 빔), 그래서 쪽잠 준비 화면이 "뒷자리에 사람이나 짐이 있다고 읽혀요. 맞나요?"를 물었습니다(그림 `1_…`).
- 앱을 막 켠 1~2초 안(능력 확인 전)에는 공기청정과 바람 방향이 운전석 영역(0x1)으로 보내져 거절됐습니다(20:07:0x). 능력 확인 뒤에는 됨. 쪽잠 차례는 그 뒤에 돕니다.
