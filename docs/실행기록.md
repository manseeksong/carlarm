# 칼람 실행 기록 (0.1~0.4)

2026년 11월 15일에 Pleos Connect 에뮬레이터에서 칼람 0.1(release, 서명함)을 설치해 돌려 본 기록입니다. 09:4x에 처음 판을 돌렸고, 10:0x에 문 잠금을 넣은 판, 10:3x에 쉼 알림과 'P에 서서 마저 돌려놓기'를 넣은 판을 돌렸습니다(3-5절, 3-6절).

시간대: 에뮬레이터는 처음에 미국 서부 시간대(America/Los_Angeles)여서 10:2x까지의 앱 기록 날짜가 "11월 14일 오후"로 찍혔습니다. 10:30에 `adb shell service call alarm 3 s16 Asia/Seoul`로 한국 시간대로 바꾸었고(`adb shell date` → Sun Nov 15 10:30:07 KST 2026), 지금의 그림과 영상은 바꾼 뒤에 찍었습니다. 실제로 본 것만 적었습니다. 시각은 한국 시간입니다.

## 2. 돌려 본 차례

1. release APK 설치 → 앱 켜짐 → 처음 물음 셋에 답함 → 시작 화면
2. 시작 화면에서 '빠르게 보기'를 켬(1분을 2초로, 화면 구석에 "빠르게 보기(시연용)"이 늘 보임)
3. "권하는 말 들어 보기(시험용 버튼)"를 누름
4. 쪽잠 준비 → 20분을 고르고 "20분 쪽잠 시작" → 자는 중 → 깨우는 중 → "일어났어요"를 누름 → 되돌린 화면
5. 안전 장면 1: 자는 중에 콘솔로 운전석 문을 엶 → 되돌림
6. 안전 장면 2: 자는 중에 콘솔로 기어를 D로 바꿈 → 되돌림 → 다시 P
7. 10분 쪽잠을 시작하고 아무것도 누르지 않음 → 깨운 뒤 3분째 저절로 되돌림

1~7은 문 잠금을 넣기 전 판입니다. 문 잠금을 넣은 판은 3-5절에 따로 적었습니다.

시작하기 전 차 상태(콘솔): 기어 P, 무드등 켜짐 흰빛 80%, 실내등 켜짐, 독서등 켜짐, 공조 전원 켜짐, 운전석 온도 24.0℃, 풍량 3, 내기 순환 켜짐, 시트 열선 0, 문 모두 닫힘.

### 3-5. 문 잠금을 넣은 판 (10:0x)

바뀐 것: 0초에 문 잠금 상태도 적어 두고, 2초에 네 문 묶음 영역으로 잠그고, 되돌릴 때 쉬기 전 상태로 돌려놓습니다(다시 읽어 확인). 되돌릴 때는 문 잠금을 맨 먼저 돌려놓습니다. 시작 화면의 권하는 말을 한 문장 "두 시간 달렸으니 다음 쉼터에서 쉬어 가요."로 바꾸었고, 달린 시간을 못 읽으면 "이 에뮬레이터는 값을 주지 않아요(지원하지 않음)"처럼 풀어 씁니다.

시작 전 콘솔: 문 잠금 풀림, 실내등과 독서등 켜짐, 무드등 70, 공조 24.0℃, 풍량 3, 순환 켜짐, 시트 열선 1.

## 5. 알려진 한계

- 소리: 에뮬레이터를 소리 없이 켜서 차의 말과 칼람의 소리를 귀로 듣지 못했습니다. 차의 말은 SDK 콜백(onStart, onDone)까지, 칼람의 소리는 재생 코드가 돈 것까지만 확인했습니다.
- 쉼 알림은 앱이 켜져 있는 동안만 셉니다(뒤에서 도는 서비스가 없습니다). 권하는 때는 '쉼 없이 달린 시간' 하나뿐이고, 환기 없이 달린 시간과 시각대 같은 다른 신호는 0.1에 없습니다. 쉼터까지 거리와 경유지도 없습니다.
- 이번 주행의 달린 시간은 에뮬레이터에서 읽히지 않았습니다(`ERROR_NOT_SUPPORTED_PROPERTY`).
- 운전석 탑승 값이 에뮬레이터에서 콘솔과 다르게 읽혀 "자리가 빔" 되돌리기는 확인하지 못했습니다.
- 기어가 D일 때는 실내등, 독서등, 문 잠금 풀기 요청이 거절되었습니다. 칼람은 기어가 P를 벗어나는 순간 되돌리고, 거절된 장치는 다시 P에 섰을 때 한 번 더 돌려놓습니다. 그래도 안 되면 화면에 이름을 적습니다.
- 되돌리기는 장치를 하나씩 보내고 다시 읽어 확인하므로 모두 끝나기까지 약 8~12초가 걸렸습니다.
- 무드등 색, 시트 열선은 쉬기 전 값을 적어 두고 되돌리지만, 이번 시험에서는 바뀌지 않아 되돌리는 장면은 보지 못했습니다(확인 전).
- 설계의 Should와 Could 줄(창문 알림, 노을빛, 김 서림 제거, 시트 통풍, 쉼터 경유지 등)은 0.1에 넣지 않았습니다.
- 가정한 값: 온도 +1℃와 −3℃의 기준은 쉬기 전 온도, 입면 소리는 5분부터 줄여 8분에 끔, 깨운 뒤 3분째에는 실내등을 켠 다음 쉬기 전 값으로 되돌림, 운전석 탑승은 시작할 때 앉아 있던 경우에만 봄.
- 시험용 진입점: `adb shell am start -n kr.carlarm.app/.MainActivity --es ambientTest "100,50,20,0,70"`로 무드등 밝기를 차례로 보내고, `--es devTest "장치:값"`(amb, ambsw, cabin, lock, lockcap, fan, recirc, seatheat, read, trip, speak, recircwatch, color, aaos)으로 장치 하나를 바꾼 뒤 다시 읽은 값을 logcat(태그 `Carlarm`)에 적습니다. 속도 권한(`CAR_SPEED`)은 이 시험용 읽기 때문에만 선언되어 있습니다.

덧붙임(11월 15일 11시 무렵): 달린 시간을 0으로 돌리는 기준을 P에 10분에서 15분으로 바꾼 판을 다시 빌드해 설치하고 켜지는 것까지 보았습니다(앱 죽음 0). 이 판으로 쉼 알림과 쪽잠 한 바퀴를 처음부터 다시 돌려 보지는 않았습니다. 위 3-1~3-6절의 결과는 10분 판에서 본 것이고, 바뀐 것은 이 숫자 하나입니다.

## 6. 0.2 판 (11월 15일 14:36~14:59)

0.2에서 바꾼 것: 쪽잠과 쉼 알림이 도는 동안만 앞에서 도는 서비스(`CarlarmService`)가 앱을 지킵니다. 쉬기 전 값과 시작 시각을 차 안에 적어 두고, 앱이 죽었다 다시 켜지면 남은 차례부터 잇습니다. 깨운 뒤 3분 동안 답이 없으면 문 잠금은 잠근 채로 두고 나머지만 되돌립니다(되돌린 화면에 "문 잠금 풀기"). 되돌리기를 시작하면 차례 번호를 올려 앞 차례의 늦은 다시 읽기와 재시도를 버립니다. 시트 열선은 공조와 상관없이 T−1분에 끕니다. 문 열림은 알림(`registerDoorPosition`)으로 받고 2초마다 읽기는 받침으로 둡니다. 쉼 알림에 내기 순환으로 달린 시간(40분), 미룬 뒤의 말(30분 뒤 한 번), 한 주행 세 번까지, 밤과 낮 1~3시의 90분 기준을 넣었습니다. 기어 알림은 화면이 없어도 쪽잠에 바로 닿습니다.

### 9-3. 알아 둔 한계 (17:16, 실제 시간 10분 쪽잠을 한 번 더 돌리며)

- 알람이 보이는 모양: 알람을 걸어 둔 동안 상태 표시줄과 알림판 어디에도 알람 표시가 보이지 않았습니다(에뮬레이터 그림으로 확인). 실제 차에서 "다음 알람" 표시가 생기는지는 확인 전입니다.
- 가상 콘솔이 꺼진 동안(브라우저 세션이 없을 때) 쪽잠을 돌리면, 앱이 보낸 값은 차에 들어가는데 다시 읽기가 옛 값을 돌려줘 되돌리기가 "바뀐 것 없음"으로 끝나고 차가 쉬는 상태(문 잠김, 빛 꺼짐, 바람 1, 25℃)로 남았습니다. 콘솔로 바로 평소 값에 돌려놓았습니다. 앱이 "다시 읽은 값이 쉬기 전과 같으면 보내지 않는" 방식이라 생긴 일이고, 다음 단계에서는 칼람이 바꾼 장치에 쉬기 전 값을 한 번 더 보내게 합니다.
- 재우는 중 화면(시작 뒤 첫 1분)에서는 화면을 눌러도 "일찍 깼어요"가 나오지 않습니다. 그 1분 동안은 문을 열거나 기어를 옮겨야 쪽잠이 끝납니다.
- 두 번 죽인 뒤 알람으로 이어 깨울 때는 되살리기에 약 3초가 걸립니다. 빠르게 보기에서는 그 3초가 90초여서 깨우기 시작의 빛 켜기를 건너뛰었고(무드등은 3분째 되돌림 때 80으로 돌아옴), 실제 시간으로 두 번 죽인 경우는 돌려 보지 않았습니다.
- `USE_EXACT_ALARM`은 알람 앱용 권한입니다. Pleos 앱 마켓 심사에서 어떻게 보는지는 확인 전입니다.

0.3.1에서도 하지 못한 것: 세로 창, 소리를 귀로 듣기, 칼람을 앱 목록에서 밀어 닫은 경우, 실제 차에서 알람과 알림이 뜨는 모양.

## 10. 제출 직전 고침: 출시판에서 시험용 입구 닫기 (11월 15일 18:52)

시험할 때 adb로 차 값을 바꾸던 인텐트 입구(`devTest`, `ambientTest`)가 출시판(release)에도 열려 있었습니다. 칼람 화면은 런처 화면이라 내보낸(exported) 상태여서, 같은 차의 다른 앱이 이 값을 담아 칼람을 열면 칼람의 권한으로 문 잠금 같은 차 값을 바꿀 수 있었습니다(외부 점검에서 찾음). 그래서 두 입구를 디버그 빌드에서만 받게 고쳤습니다(`MainActivity.testHooks`, 앱의 디버그 가능 표시로 가림). 화면과 기능은 0.3.1과 같습니다.

| 확인 | 본 것 | 판정 |
|---|---|---|
| 출시판 설치와 켜기 | 고친 release APK를 깔아 켜자 프로세스가 살아 있고 차 SDK 초기화 기록이 남음. 칼람의 FATAL 0건 | 됨 |
| 시험용 입구 | 칼람이 켜진 채 `devTest`로 `read`(값 읽기)와 `lock:false`(문 풀기)를 보냄. 입구가 열려 있으면 남는 기록 "장치 시험"이 0줄 | 됨(막힘) |
| 디버그 가능 표시 | 설치된 출시판의 디버그 가능 표시 없음 | 됨 |
